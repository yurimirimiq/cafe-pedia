# 카페피디아 개발 로드맵

웹사이트 배포까지의 단계별 할 일. 위에서부터 순서대로 진행하고, 끝난 항목은 `[x]`로 체크한다.

## 기술 스택 (추천안)

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 백엔드 | Django + Django REST Framework | 파이썬 경험 활용, 로그인·관리자 페이지 기본 제공. API로 만들어 두면 나중에 앱에서 그대로 재사용 |
| 프론트엔드 | React (Vite) | 웹 화면을 API와 분리. 나중에 React Native로 넘어갈 때 익숙함 |
| DB | 개발: SQLite / 배포: PostgreSQL | SQLite는 설치가 필요 없고, 배포 환경에서는 PostgreSQL이 표준 |
| 인증 | JWT (djangorestframework-simplejwt) | 프론트와 백엔드 주소가 달라도 쓰기 쉬움 |
| 외부 API | 카카오 로컬 API, 카카오 지도 JS API | 카페 검색, 지도 표시 |
| 배포 | 백엔드: Render / 프론트: Vercel | 둘 다 GitHub 연결만으로 자동 배포 |

> 더 빨리 끝내고 싶다면 React 없이 Django 템플릿만 쓰는 방법도 있다. 대신 앱을 만들 때 서버를 많이 고쳐야 한다.

## 폴더 구조 (예정)

```
cafe-pedia/
├── backend/     # Django 프로젝트 (API 서버)
├── frontend/    # React 프로젝트 (웹 화면)
├── docs/        # 시안, 로드맵
└── README.md
```

## 0단계: 준비 (1주차 초)

- [x] 개발 도구 설치: Python 3.12+, Node.js LTS, VS Code
- [x] [카카오 개발자](https://developers.kakao.com)에서 애플리케이션 등록
  - [x] REST API 키 발급 (카페 검색용, 서버에서 사용)
  - [ ] JavaScript 키 발급 (지도 표시용, 브라우저에서 사용)
  - [ ] 플랫폼에 `http://localhost:5173` 등록
- [x] 기술 스택 최종 결정 → README의 "미정 사항" 업데이트

**완료 기준**: 키 두 개를 `.env`에 넣었고, 어떤 기술로 만들지 정했다.

## 1단계: 프로젝트 세팅 (1주차)

- [x] `backend/`: 가상환경(venv) 만들기, Django·DRF 설치, `requirements.txt` 작성
- [x] `frontend/`: Vite로 React 프로젝트 생성, Pretendard 글꼴과 색 변수(README 디자인 방향) 적용
- [x] 프론트에서 백엔드 API를 호출할 수 있게 CORS 설정 (`django-cors-headers`)
- [x] `.env`로 비밀값 관리 (`SECRET_KEY`, 카카오 키), `.env.example` 파일 커밋

**완료 기준**: 백엔드(`localhost:8000`)와 프론트(`localhost:5173`)가 둘 다 실행되고, 프론트 화면에 백엔드에서 받은 "hello"가 보인다.

## 2단계: DB 모델 설계 (1주차)

- [x] `Place`: 카카오 장소 ID(고유값), 분류(카페 `CE7` / 식당 `FD6`), 세부 분류, 이름, 주소, 위도·경도
- [x] `Review`: 사용자, 장소, 별점(0.5~5.0, 0.5 단위), 한 줄 평, 방문일(캘린더용), 작성일
  - 사용자·장소 쌍마다 1개만 (같은 곳을 두 번 평가하면 수정으로 처리)
- [x] `Wishlist`("가고 싶어요"): 사용자, 장소
- [x] Django 관리자 페이지에 모델 등록 → 데이터를 눈으로 확인

**완료 기준**: 관리자 페이지에서 장소와 리뷰를 직접 추가·조회할 수 있다.

## 3단계: 회원가입 / 로그인 (1주차)

- [x] 회원가입 API (아이디, 닉네임, 비밀번호) — 닉네임이 있는 사용자 모델(`User`)은 2단계에서 만들어 둠
- [x] 로그인 API → JWT 토큰 발급
- [x] 프론트: 회원가입·로그인 화면, 토큰 저장, 로그인 상태에 따라 메뉴 바꾸기

**완료 기준**: 가입 → 로그인 → 새로고침해도 로그인 상태가 유지된다.

## 4단계: 장소 검색 (2주차)

- [x] 백엔드에서 카카오 로컬 API 호출 (카테고리 `CE7` 카페 + `FD6` 음식점만)
  - 카카오 키가 브라우저에 노출되지 않도록 반드시 서버에서 호출
- [x] 검색 결과의 장소를 DB에 저장 (카카오 장소 ID로 중복 방지)
- [x] 프론트: 검색 페이지 (검색창 → 검색 결과 목록, 카페 / 식당 표시)

**완료 기준**: "망원동 카페", "망원동 국밥"을 검색하면 실제 장소 목록이 나온다.

## 5단계: 별점 / 한 줄 평 (2주차)

- [x] 별점 등록·수정·삭제 API (로그인한 사용자만, 0.5 단위 검사)
- [x] 장소 상세 API: 장소 정보 + 평균 별점 + 평가 수 + 한 줄 평 목록
- [x] "가고 싶어요" 추가·취소 API
- [x] 프론트: 장소 상세 페이지 (시안 기준 3단 구성), 별점 매기기, 방문일 선택
- [ ] 카카오 지도 표시 — 코드는 준비됨, `frontend/.env`에 `VITE_KAKAO_JS_KEY`를 넣으면 켜짐 (없으면 카카오맵 링크만 표시)

**완료 기준**: 장소에 별점을 주면 평균 별점이 바로 바뀐다.

## 6단계: 홈 / 캘린더 / 나의 기록 (3주차)

- [x] 공통 레이아웃: 메뉴 4개(홈 / 검색 / 캘린더 / 나의 기록) — 데스크톱은 상단 바, 모바일 폭은 하단 탭 바
- [x] 홈 API: 전체 평가 수, 이번 주 가장 많이 평가된 곳, 분류(카페 / 식당)별 인기 랭킹, 최근 평가된 곳
- [x] 내 주변: 위치 권한 → 카카오 카테고리 검색(반경, 가까운 순) → 거리·별점 목록, 카페 / 식당·거리·정렬 필터
- [ ] 홈 "동네별" 줄 — 장소에 동(洞) 정보를 따로 저장해야 해서 나중에
- [x] 캘린더 API: 월을 주면 그 달에 방문한 장소 목록 (방문일 기준, 분류 필터)
- [x] 나의 기록 API: 평가 / 한 줄 평 / 가고 싶어요 수, 보관함(카페 / 식당), 별점 분포
- [x] 프론트: 홈(분류 탭, 바로가기, 포스터 줄), 캘린더(달력 칸에 포스터), 나의 기록 페이지
- [x] 사진이 없는 장소는 커피색 타일 + 첫 글자로 표시

**완료 기준**: README "화면 구성"의 화면이 모두 실제 데이터로 동작한다.

## 6.2단계: 키워드 태그 (3~4주차)

> 장소를 누르면 "커피 맛집 · 디저트 · 조용함"처럼 2~3개 키워드로 간단히 보여준다

- [x] 태그 목록 정하기 (카페: 커피 맛집 / 디저트 / 작업하기 좋음 / 조용함 / 뷰 맛집 / 대화하기 좋음, 식당: 혼밥 / 가성비 / 양 많음 / 데이트 / 웨이팅 있음 등)
- [x] 별점 남길 때 태그 최대 3개 고르기 (리뷰에 저장)
- [x] 장소별로 가장 많이 선택된 태그 2~3개를 상세·카드·검색 결과에 표시
- [x] 태그가 없을 땐 카카오 세부 분류(예: 디저트카페, 국밥)를 대신 보여준다
- [ ] 나중에: 태그별 랭킹, 추천 알고리즘에 태그 반영

## 6.25단계: 장소 썸네일 사진

- [x] 카카오 공식 이미지 검색 API로 "가게 이름 + 구" 검색 → 첫 결과의 썸네일과 출처 글 주소를 장소에 저장 (한 번만 찾음)
- [x] 포스터에 사진 표시, 사진이 없거나 깨지면 커피색 타일로 대체, 상세에 "사진 출처 보기" 링크
- [ ] 검색 결과가 엉뚱한 사진일 수 있음 → 관리자 페이지에서 사진 지우기·바꾸기, 리뷰 사진이 생기면 리뷰 사진 우선

## 6.3단계: 카카오 로그인 (3~4주차)

> 아이디·비밀번호 가입은 그대로 두고, "카카오로 시작하기"를 추가한다

- [x] 카카오 개발자 콘솔: 카카오 로그인 켜기, Client Secret 을 `backend/.env` 의 `KAKAO_CLIENT_SECRET` 에 저장, Redirect URI 등록(`http://localhost:5173/auth/kakao`), 동의 항목(닉네임) 설정
- [x] 백엔드: 프론트가 받은 인가 코드 → 카카오 토큰 → 카카오 사용자 정보 → 우리 회원 찾기/만들기 → 우리 JWT 발급
  - 카카오 회원 번호를 저장할 칸 추가, 비밀번호 없는 회원으로 만든다
  - 닉네임이 이미 있으면 뒤에 숫자를 붙인다
- [x] 프론트: 로그인·회원가입 화면에 "카카오로 시작하기" 버튼, `/auth/kakao` 콜백 페이지
- [x] 테스트: 카카오 API를 가짜로 바꿔 신규 가입·재로그인·닉네임 중복 확인

**완료 기준**: 카카오 버튼 한 번으로 가입되고, 다음에도 같은 계정으로 로그인된다.

## 6.4단계: 리뷰 사진 올리기

- [x] 별점·한 줄 평을 남길 때 사진 최대 3장 (용량·형식 검사, 서버에서 크기 줄이기)
- [x] 개발 중에는 `backend/media/`에 저장 (크기 줄이고 촬영 위치 EXIF 삭제)
- [ ] 배포할 때는 이미지 저장소(Cloudinary 또는 S3)로 — Render 서버 디스크는 재시작하면 지워짐
- [x] 상세 페이지에 리뷰 사진 모아 보기, 장소 포스터는 리뷰 사진을 검색 썸네일보다 우선

## 6.45단계: 영수증 인증

- [x] 영수증 사진 → CLOVA OCR → 가게 이름(이름 또는 도로명 주소)·결제일(오늘 이전 90일 이내) 확인
- [x] 같은 영수증 재사용 막기: 승인번호(없으면 날짜·금액·시각)로 만든 지문만 저장, 사진은 저장하지 않음
- [x] 인증되면 방문일을 결제일로 맞추고 고정, 리뷰에 인증 배지
- [x] 장소 상세: 한 줄 평 "전체 / 영수증 인증" 탭, 인증된 사람들만의 평균 별점
- [ ] CLOVA OCR 가입·키 발급 후 `.env` 에 넣고 실제 영수증으로 확인 ← 직접 해야 함
- [ ] 나중에: 인증 평균을 랭킹·추천에 반영

## 6.5단계: 취향 기반 추천 (3~4주차)

> 별점 데이터가 쌓여야 의미가 있어서, 별점 기능(5단계) 이후에 만든다. 방식은 README "추천 알고리즘" 참고

- [ ] 사용자 간 유사도 계산 (같이 평가한 곳 3곳 이상, 평균을 뺀 별점으로 피어슨 상관계수)
- [ ] 예상 별점 API: 장소 하나에 대한 내 예상 별점
- [ ] 추천 목록 API: 예상 별점 높은 순, 카페 / 식당 / 동네 필터
- [ ] 콜드 스타트 대체 추천 (동네 인기 + 내가 좋아한 세부 분류)
- [ ] 프론트: 검색 화면 "좋아할 만한 곳", 장소 상세의 "예상 ★4.3"
- [ ] 테스트: 작은 가짜 데이터로 "취향 비슷한 사람이 좋아한 곳이 위에 오는지" 확인
- [ ] 7단계 데이터 채우기 때 지인 몇 명에게 10곳 이상씩 평가를 부탁해 실제로 동작하는지 확인

**완료 기준**: 별점을 10개쯤 남긴 사용자에게, 아직 안 가본 곳이 예상 별점과 함께 추천된다.

## 7단계: 다듬기 (3주차)

- [ ] 반응형: 화면이 좁아지면 포스터 수 줄이기, 모바일에서도 쓸 수 있게
- [ ] 빈 화면 처리 ("아직 평가가 없어요. 첫 별점을 남겨보세요")
- [ ] 에러 처리 (검색 실패, 로그인 만료 등)
- [ ] 핵심 API 테스트 작성 (별점 0.5 단위 검사, 중복 평가 방지)
- [ ] 직접 가본 카페·식당 20~30곳 미리 평가해서 데이터 채우기

**완료 기준**: 처음 보는 사람이 설명 없이 검색부터 평가까지 할 수 있다.

## 8단계: 배포 (4주차)

- [ ] 배포용 PostgreSQL 준비, 백엔드 설정 분리 (`DEBUG=False`, 허용 도메인)
- [ ] 백엔드 → Render, 프론트 → Vercel 배포 (환경변수 등록)
- [ ] 카카오 개발자 콘솔에 배포 도메인 등록
- [ ] (선택) 도메인 구입 후 연결 (예: cafepedia.kr)

**완료 기준**: 다른 사람 폰에서 주소를 열어 가입하고 별점을 남길 수 있다.

## 9단계: 공개 준비 (4주차)

- [ ] 개인정보처리방침, 이용약관 페이지
- [ ] 카카오 지도 출처 표시
- [ ] 방문자 분석 도구 연결 (Google Analytics 등)
- [ ] README 정리: 실제 화면 스크린샷, 기술 선택 이유, 배포 주소

**완료 기준**: 지인에게 링크를 보내 홍보를 시작할 수 있다.
