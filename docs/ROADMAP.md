# 카페피디아 개발 로드맵

웹사이트 배포까지의 단계별 할 일. 위에서부터 순서대로 진행하고, 끝난 항목은 `[x]`로 체크한다.

## 기술 스택 (추천안)

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 백엔드 | Django + Django REST Framework | 파이썬 경험 활용, 로그인·관리자 페이지 기본 제공. API로 만들어 두면 나중에 앱에서 그대로 재사용 |
| 프론트엔드 | React (Vite) | 웹 화면을 API와 분리. 나중에 React Native로 넘어갈 때 익숙함 |
| DB | 개발: SQLite / 배포: PostgreSQL | SQLite는 설치가 필요 없고, 배포 환경에서는 PostgreSQL이 표준 |
| 인증 | JWT (djangorestframework-simplejwt) | 프론트와 백엔드 주소가 달라도 쓰기 쉬움 |
| 외부 API | 카카오 로컬 API, 카카오 지도 JS API | 카페 검색, 지도 표시 |
| 배포 | 백엔드: Render / 프론트: Vercel | 둘 다 GitHub 연결만으로 자동 배포 |

> 더 빨리 끝내고 싶다면 React 없이 Django 템플릿만 쓰는 방법도 있다. 대신 앱을 만들 때 서버를 많이 고쳐야 한다.

## 폴더 구조 (예정)

```
cafe-pedia/
├── backend/     # Django 프로젝트 (API 서버)
├── frontend/    # React 프로젝트 (웹 화면)
├── docs/        # 시안, 로드맵
└── README.md
```

## 0단계: 준비 (1주차 초)

- [ ] 개발 도구 설치: Python 3.12+, Node.js LTS, VS Code
- [ ] [카카오 개발자](https://developers.kakao.com)에서 애플리케이션 등록
  - [ ] REST API 키 발급 (카페 검색용, 서버에서 사용)
  - [ ] JavaScript 키 발급 (지도 표시용, 브라우저에서 사용)
  - [ ] 플랫폼에 `http://localhost:5173` 등록
- [ ] 기술 스택 최종 결정 → README의 "미정 사항" 업데이트

**완료 기준**: 키 두 개를 `.env`에 넣었고, 어떤 기술로 만들지 정했다.

## 1단계: 프로젝트 세팅 (1주차)

- [ ] `backend/`: 가상환경(venv) 만들기, Django·DRF 설치, `requirements.txt` 작성
- [ ] `frontend/`: Vite로 React 프로젝트 생성, Pretendard 글꼴과 색 변수(README 디자인 방향) 적용
- [ ] 프론트에서 백엔드 API를 호출할 수 있게 CORS 설정 (`django-cors-headers`)
- [ ] `.env`로 비밀값 관리 (`SECRET_KEY`, 카카오 키), `.env.example` 파일 커밋

**완료 기준**: 백엔드(`localhost:8000`)와 프론트(`localhost:5173`)가 둘 다 실행되고, 프론트 화면에 백엔드에서 받은 "hello"가 보인다.

## 2단계: DB 모델 설계 (1주차)

- [ ] `Cafe`: 카카오 장소 ID(고유값), 이름, 주소, 위도·경도
- [ ] `Review`: 사용자, 카페, 별점(0.5~5.0, 0.5 단위), 한 줄 평, 작성일
  - 사용자·카페 쌍마다 1개만 (같은 카페를 두 번 평가하면 수정으로 처리)
- [ ] `Wishlist`("가고 싶어요"): 사용자, 카페
- [ ] Django 관리자 페이지에 모델 등록 → 데이터를 눈으로 확인

**완료 기준**: 관리자 페이지에서 카페와 리뷰를 직접 추가·조회할 수 있다.

## 3단계: 회원가입 / 로그인 (1주차)

- [ ] 회원가입 API (아이디, 닉네임, 비밀번호)
- [ ] 로그인 API → JWT 토큰 발급
- [ ] 프론트: 회원가입·로그인 화면, 토큰 저장, 로그인 상태에 따라 메뉴 바꾸기

**완료 기준**: 가입 → 로그인 → 새로고침해도 로그인 상태가 유지된다.

## 4단계: 카페 검색 (2주차)

- [ ] 백엔드에서 카카오 로컬 API 호출 (카테고리 `CE7` = 카페로 제한)
  - 카카오 키가 브라우저에 노출되지 않도록 반드시 서버에서 호출
- [ ] 검색 결과의 카페를 DB에 저장 (카카오 장소 ID로 중복 방지)
- [ ] 프론트: 상단 검색창 → 검색 결과 목록

**완료 기준**: "망원동 카페"를 검색하면 실제 카페 목록이 나온다.

## 5단계: 별점 / 한 줄 평 (2주차)

- [ ] 별점 등록·수정·삭제 API (로그인한 사용자만, 0.5 단위 검사)
- [ ] 카페 상세 API: 카페 정보 + 평균 별점 + 평가 수 + 한 줄 평 목록
- [ ] "가고 싶어요" 추가·취소 API
- [ ] 프론트: 카페 상세 페이지 (시안 기준 3단 구성), 별점 매기기, 카카오 지도 표시

**완료 기준**: 카페에 별점을 주면 평균 별점이 바로 바뀐다.

## 6단계: 홈 / 내 기록 (3주차)

- [ ] 홈 API: 동네별·태그별 평균 별점 높은 카페 목록
- [ ] 내 기록 API: 내가 평가한 카페, 별점 분포, 가고 싶어요 목록
- [ ] 프론트: 홈 화면(포스터 줄), 내 기록 페이지
- [ ] 사진이 없는 카페는 커피색 타일 + 첫 글자로 표시

**완료 기준**: 시안에 있는 화면이 모두 실제 데이터로 동작한다.

## 7단계: 다듬기 (3주차)

- [ ] 반응형: 화면이 좁아지면 포스터 수 줄이기, 모바일에서도 쓸 수 있게
- [ ] 빈 화면 처리 ("아직 평가가 없어요. 첫 별점을 남겨보세요")
- [ ] 에러 처리 (검색 실패, 로그인 만료 등)
- [ ] 핵심 API 테스트 작성 (별점 0.5 단위 검사, 중복 평가 방지)
- [ ] 직접 가본 카페 20~30곳 미리 평가해서 데이터 채우기

**완료 기준**: 처음 보는 사람이 설명 없이 검색부터 평가까지 할 수 있다.

## 8단계: 배포 (4주차)

- [ ] 배포용 PostgreSQL 준비, 백엔드 설정 분리 (`DEBUG=False`, 허용 도메인)
- [ ] 백엔드 → Render, 프론트 → Vercel 배포 (환경변수 등록)
- [ ] 카카오 개발자 콘솔에 배포 도메인 등록
- [ ] (선택) 도메인 구입 후 연결 (예: cafepedia.kr)

**완료 기준**: 다른 사람 폰에서 주소를 열어 가입하고 별점을 남길 수 있다.

## 9단계: 공개 준비 (4주차)

- [ ] 개인정보처리방침, 이용약관 페이지
- [ ] 카카오 지도 출처 표시
- [ ] 방문자 분석 도구 연결 (Google Analytics 등)
- [ ] README 정리: 실제 화면 스크린샷, 기술 선택 이유, 배포 주소

**완료 기준**: 지인에게 링크를 보내 홍보를 시작할 수 있다.
